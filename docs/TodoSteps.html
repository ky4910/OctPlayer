FFmpeg + Qt + SDL 播放器推荐实现步骤

面向可复用播放器内核的分阶段路线，优先建立状态、生命周期、命令、时钟和输出适配器边界，再逐步加入解码、渲染、Seek、字幕、倍速、硬件解码与网络流。
实施目录第一阶段：先把播放器骨架跑起来第二阶段：完成 FFmpeg 基础能力第三阶段：优先打通音频第四阶段：完成视频解码与调度第五阶段：完成 Qt Quick 视频显示第六阶段：让本地文件播放真正可用第七阶段：建设常用播放器能力第八阶段：高级能力推荐里程碑
实施原则：不要以“尽快看到画面”为唯一目标。优先保证 Session 生命周期、AudioClock、FrameScheduler 和 Renderer 边界正确，这四部分稳定后，后续扩展通常不需要推翻整体结构。
PHASE 1

第一阶段：先把播放器骨架跑起来

先保证状态、命令和生命周期正确，即使暂时还没有真正的音视频输出。

1. 实现状态机

完成 Idle、Opening、Ready、Playing、Paused、Stopping、Error 等状态及合法转换。先为 StateMachine 编写单元测试，确保未打开时不能播放、失败后能回滚、Stop 后回到稳定状态。

2. 实现 Command Queue

将 open、play、pause、stop、seek 等请求统一转换成命令，经由 UI → Command Queue → Player Control Thread → PlaybackSession 串行执行，避免 UI 线程直接跨线程调用解码器。

3. 建立 Session 生命周期

每次 open 创建独立 PlaybackSession，引入 sessionId 和 generation。切换媒体时取消旧 Session，并忽略旧 Session 迟到的帧、EOF、错误及状态事件。

PHASE 2

第二阶段：完成 FFmpeg 基础能力

目标是可以打开媒体、识别流并读取 Packet，暂时不做解码。

4. 实现 FfmpegDemuxer

封装 avformat_open_input、avformat_find_stream_info、关闭和错误转换。输出 MediaInfo，包括时长、音视频流索引、分辨率、采样率、声道和可 Seek 能力。

5. 引入 Packet 和 PacketQueue

使用 RAII 包装 AVPacket，建立 AudioPacketQueue、VideoPacketQueue 和可选的 SubtitlePacketQueue。Demux 线程读取包后按 stream index 分发，并支持 flush、abort、close 和 reset。

PHASE 3

第三阶段：优先打通音频

音频通常作为播放器主时钟，因此建议先让播放器稳定发声。

6. 实现 AudioDecoder

根据音频流参数创建 AVCodecContext，使用 avcodec_send_packet 和 avcodec_receive_frame 输出解码音频帧，并支持 flush 和 drain。

7. 实现音频重采样

使用 libswresample 将输入统一转换成 SDL 输出所需格式。第一版可固定为 48 kHz、S16、双声道，再逐步增加设备格式协商。

8. 完成 SDL2 AudioSink

推荐使用 SDL callback + PCM RingBuffer。解码线程写入 RingBuffer，SDL 音频线程按设备节奏消费。第一版也可先使用 SDL_QueueAudio，但必须封装在 AudioSink 内。

9. 建立 AudioClock

基于实际已播放样本数和设备缓冲延迟计算音频时钟，而不是使用解码到达时间。验证 position 能连续、稳定增长，并在 pause、seek、stop 后正确变化。

PHASE 4

第四阶段：完成视频解码与调度

目标是稳定解出 VideoFrame，并根据主时钟决定显示时间。

10. 实现 VideoDecoder

根据视频流创建解码器，建立 VideoPacketQueue → VideoDecoder → VideoFrame 的链路。第一版优先支持软件解码和 YUV420P。

11. 定义 VideoFrame 边界

VideoFrame 携带 PTS、sessionId、generation、尺寸、像素格式、色彩信息和底层存储引用。Core、Qt 和渲染层之间不传裸 AVFrame 指针。

12. 实现 FrameScheduler

使用 AudioClock 作为默认 MasterClock，计算 videoPts - masterClock.now()。视频超前时做可中断等待，接近目标时间时提交，明显落后时按策略丢帧。

PHASE 5

第五阶段：完成 Qt Quick 视频显示

目标是在 QQuickFramebufferObject 中看到正确画面。

13. 实现 VideoFrameMailbox

Scheduler 将帧提交到 latest-frame mailbox。Renderer 每次只取最新待显示帧，避免 UI 变慢时积累大量过期帧。

14. 完成 VideoOutputItem 与 Renderer

VideoOutputItem 只负责 QML 属性、尺寸和 update 触发；VideoOutputRenderer 只负责渲染线程中的 OpenGL 操作；两者通过 synchronize() 转移轻量状态和帧引用。

15. 实现 YUV Shader

第一版为 Y、U、V 三个 GL_R8 纹理，片段着色器完成 YUV420P 到 RGB 转换。正确处理 linesize、宽高比、色彩范围和 BT.601/BT.709 差异。

PHASE 6

第六阶段：让本地文件播放真正可用

集中解决 Seek、EOF、暂停和缓冲等边界问题。

16. 完整实现 Seek

流程建议为：进入 Seeking → 暂停输出 → 唤醒并清空队列 → Flush Audio/Video Sink → avcodec_flush_buffers → avformat_seek_file → generation++ → 重置时钟 → 恢复解码 → 回到 Playing 或 Paused。

17. 正确处理 EOF 和 Drain

Demux 到 EOF 后向各解码器发送结束标记，解码器用空 Packet 排空内部缓存，等待音视频输出完成后再发送 EndOfMedia。

18. 实现暂停与恢复

暂停时停止时钟和输出消费，但明确队列是否继续预缓冲。恢复时避免重复创建线程或重复连接信号。

19. 实现 BufferController

按队列包含的媒体时长而不是单纯包数量判断缓冲状态。为本地文件和网络流预留不同的低水位、高水位策略。

20. 完善 Stop 和资源释放

Stop 必须可以中断所有等待，按确定顺序退出 Demux、Decode、Scheduler 和输出模块，最后释放 FFmpeg、SDL 和 OpenGL 相关资源。

PHASE 7

第七阶段：建设常用播放器能力

内核稳定后，再通过已有边界扩展功能。

21. TrackManager 与轨道切换

统一管理音轨、视频轨和字幕轨。切换轨道时只重建相关 Decoder 和队列，不重建整个 UI。

22. 字幕管线

增加 SubtitlePacketQueue、SubtitleDecoder 和 SubtitleEvent，根据 MasterClock 调度显示，可由 QML Overlay 或专用渲染器输出。

23. 倍速播放

视频调度和 MediaClock 支持 rate；音频增加时间拉伸或变速策略。第一版可限制为几个固定倍率。

24. 截图

从当前 VideoFrame 导出 QImage 或编码图片。截图能力应作为 VideoFrame 的消费者，而不是直接侵入 Decoder。

25. 音量、静音和设备切换

在 AudioSink 或独立 AudioProcessor 中处理音量与静音；设备切换通过重开 AudioSink 完成，不让播放状态机直接依赖 SDL API。

PHASE 8

第八阶段：高级能力

最后再进入硬解、网络流、零拷贝和高阶色彩管理。

26. 硬件解码抽象

定义 IDecoder 或 DecoderFactory，逐步加入 VAAPI、D3D11VA、V4L2 M2M 等后端，同时保留软件解码回退。

27. 零拷贝与 HardwareSurface

扩展 VideoFrame 存储类型，使 DMA-BUF、D3D11 Texture 或其他硬件 Surface 可以直接进入渲染适配器。

28. 网络流和重连

增加超时、中断回调、缓冲策略、网络错误分类和断线重连。不要把网络特例硬编码进 UI。

29. 色彩管理与 HDR

完善色彩空间、范围、原色、传递函数和 Tone Mapping，确保渲染器根据帧元数据选择正确转换路径。

30. 播放列表与历史记录

将 PlaylistManager、最近播放和断点续播放在播放器内核之外，通过 IPlayer 和事件接口驱动。

ROADMAP

推荐里程碑

每个里程碑都应形成可以独立验证的结果。
