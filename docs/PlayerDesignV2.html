OctPlayer - FFmpeg + Qt + SDL3 播放器架构说明

本项目当前是一个以 Qt Quick 为 UI，FFmpeg 负责解封装与解码，SDL3 负责音频输出，QQuickFramebufferObject 负责视频渲染的播放器骨架。

1. 项目综述

这个项目的目标是搭建一个“可扩展的播放器内核”，而不是仅仅做一个单文件 Demo。当前代码已经具备以下几个关键骨架：

  • Qt 6 + QML 应用入口
  • FFmpeg 相关封装（demuxer/RAII）
  • SDL3 音频输出适配
  • 视频最新帧邮箱（mailbox）
  • Qt Quick 渲染对象（QQuickFramebufferObject）
  • 统一的 player 运行时对象和事件回调
结论：当前不是一个完整的媒体播放器产品，而是一个“播放器主干 + 边界抽象 + 可继续扩展的骨架”，适合继续实现 FFmpeg 解码、同步、缓冲和视频渲染细节。

3. 核心对象职责

3.1 Player

player::Player 是整个播放器的主入口。它持有：音频输出适配器、视频帧信箱、当前 session，并负责创建/替换 PlaybackSession。

Player::open() -> 创建新 PlaybackSession
Player::play() / pause() / stop() / seek() -> 转发给当前 session
Player::snapshot() -> 返回状态快照
Player::setEventCallback() -> 订阅状态变化事件

3.2 PlaybackSession

PlaybackSession 是一次播放会话的核心容器，持有解封装器、时钟和输出适配器。这里负责 session 生命周期、状态变化和 seek 相关边界。

PlaybackSession
 ├─ demuxer_
 ├─ clock_
 ├─ audio_
 ├─ video_
 ├─ snapshot_
 └─ event_

3.3 FfmpegDemuxer

FfmpegDemuxer 是 FFmpeg 侧的封装层，负责打开媒体源、seek 和访问 AVFormatContext。这是将 FFmpeg 细节从播放器主逻辑中隔离出来的关口。

3.4 SdlAudioSink

SdlAudioSink 实现了 IAudioSink，当前使用的是 SDL3 的流式音频接口（SDL_AudioStream / SDL_OpenAudioDeviceStream 这类 API），而不是 SDL2 的旧式 SDL_QueueAudio 方案。

IAudioSink
 ├─ open()
 ├─ start()/pause()
 ├─ flush()
 ├─ close()
 ├─ write()
 └─ playedTime()

3.5 VideoFrameMailbox

VideoFrameMailbox 是视频渲染前的最新帧缓存，作用相当于“只保留最后一帧”的桥接对象。它让渲染器不必处理无限增长的帧队列。

3.6 QtPlayerAdapter

QtPlayerAdapter 是连接 QML 和内部播放器的桥接层。它暴露 QML 可调用的方法，如 open()、play()、pause()、stop() 等，并通过 Qt 属性暴露播放状态和位置。

3.7 VideoOutputItem / VideoOutputRenderer

VideoOutputItem 是 QML 可用的自定义控件，VideoOutputRenderer 是它的 OpenGL 渲染器。通过 QQuickFramebufferObject，可以在 Qt Quick 场景中插入自定义视频渲染内容。

4. 数据流和事件流

QML / UI
   │
   ▼
QtPlayerAdapter
   │
   ▼
Player
   │
   ▼
PlaybackSession
   │   ├─ FFmpeg demuxer -> packets
   │   ├─ AudioSink -> SDL3 playback
   │   └─ VideoFrameMailbox -> QQuickFramebufferObject
   │
   └─ PlayerEvent -> Qt signals / stateChanged / positionChanged

从设计上讲，这条链路允许 UI 层只访问稳定的 Qt/Player 接口，而不必直接依赖 FFmpeg 或 SDL API。

当前代码的实现已经把“播放器状态变化”和“音视频输出适配器”做成了明确边界，但真正的音视频解码线程、packet queue、frame queue、同步策略、seek/generation 校验等仍有待补全。

6. SDL3 相关说明

当前项目已经从 SDL2 旧接口迁移到 SDL3 的常见方式，关键点包括：

  • 使用 find_package(SDL3 REQUIRED) 来解析库和头文件
  • 使用 #include <SDL3/SDL.h>
  • 使用 SDL3 的音频格式常量，例如 SDL_AUDIO_S16
  • 使用 SDL3 音频设备流接口：SDL_OpenAudioDeviceStream()、SDL_PutAudioStreamData()、SDL_GetAudioStreamQueued()
  • 不要继续使用 SDL2 旧式的 AUDIO_S16SYS、SDL_QueueAudio()、SDL_GetQueuedAudioSize() 这类 API

这一点非常关键：项目的 ThirdParty 目录中实际上是 SDL3 3.2.18，因此当前代码应保持与 SDL3 一致，而不能再沿用 SDL2 的思路。

7. Qt/QML 集成方式

Main.qml 中使用了：

import OctPlayer 1.0

VideoOutput {
    id: video
    Component.onCompleted: video.setMailbox(player.videoMailbox())
}

也就是说，QML 直接调用 player.videoMailbox()，然后把返回的对象（这里被包装成 QObject 能力）传给自定义视频控件，最终由渲染线程消费最新帧供 OpenGL 绘制。

这里的设计重点是：不要把 FFmpeg/SDL/AVFrame 直接暴露给 QML。QML 只应该看到简单的信号、属性和可调用方法。

10. 实施建议

  1. 先把“解封装与解码”补全，确保能拿到 AVPacket / AVFrame。
  2. 再补音频输出：音频帧进入 SDL3 stream；计算播放时长与队列长度。
  3. 然后补视频：将 decoded frame 交给最新帧 mailbox。
  4. 最后补同步：实现 master clock、seek generation 和 stale event 移除。
重点：不要在 UI 线程中直接进行 FFmpeg 解码和 OpenGL 纹理上传。这个项目的设计目标是把“播放器逻辑”和“UI 渲染”明确分离。
