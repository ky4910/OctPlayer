FFmpeg + Qt + SDL 可复用播放器内核架构设计

使用 FFmpeg 完成解封装与解码，SDL2 负责音频输出，QQuickFramebufferObject 负责 Qt Quick 视频渲染，并通过稳定接口构建可扩展、可测试、可替换的播放器内核。

1. 总体架构

目标是构建一个基于 FFmpeg + Qt/QML + SDL2 + QQuickFramebufferObject 的播放器，同时形成稳定、可测试、可替换的播放器内核边界。

│  play() pause() seek() volume()                       │
│  QQuickFramebufferObject                              │
└──────────┬────────────────────────────────────────────┘
           │ Stable Player API
           ▼
┌──────────────── Player SDK / Facade ──────────────────┐

核心原则：UI 只认识播放器接口和事件，不认识 FFmpeg、SDL、解码线程或 AVFrame。

2. 建议的模块划分

2.1 player-api：稳定公共接口

该模块是播放器内核的公开边界，尽量不暴露 Qt、SDL 和 FFmpeg 类型。

class IPlayer {
public:
    virtual ~IPlayer() = default;
    virtual void open(MediaSource source) = 0;
    virtual void play() = 0;
    virtual void pause() = 0;
    virtual void stop() = 0;
    virtual void seek(std::chrono::milliseconds position) = 0;
    virtual void setVolume(float volume) = 0;
    virtual void setMuted(bool muted) = 0;
    virtual void setRate(double rate) = 0;
    virtual PlayerSnapshot snapshot() const = 0;
    virtual void setEventCallback(PlayerEventCallback callback) = 0;
};

公共头文件中不要出现 AVFrame*、AVPacket*、SDL_AudioSpec、QObject*、QImage 或 OpenGL 纹理类型。推荐只暴露自己的值类型。

enum class PlayerState {
    Idle, Opening, Ready, Playing, Paused,
    Seeking, Buffering, Stopping, Ended, Error
};

2.2 player-core：播放流程和状态机

  • 播放状态机与命令串行化
  • Session 生命周期
  • Demux 调度和 Packet/Frame 队列
  • 时钟、同步和缓冲策略
  • Seek、Flush、EOF 和错误传播
  • 输出适配器协调

所有状态转换应统一由 PlaybackSession 或 StateMachine 执行，Worker 不应随意修改全局播放状态。

3. 命令和事件模型

UI 的控制请求全部转换成命令，避免 GUI 线程直接跨线程调用解码器。

using PlayerCommand = std::variant<
    OpenCommand, PlayCommand, PauseCommand,
    SeekCommand, StopCommand, SetVolumeCommand,
    SetRateCommand, SelectTrackCommand
>;
Qt UI thread → ControlCommandQueue → Player control thread → PlaybackSession

事件反向传递，Qt 适配层收到内核事件后，再通过 Qt::QueuedConnection 转换为 Qt 信号和属性变化。Core 本身不依赖 Qt 信号槽。

4. 推荐线程模型

Qt GUI Thread
  QML、按钮、属性、PlayerViewModel

Qt Render Thread
  QQuickFramebufferObject::Renderer
  OpenGL 纹理上传及绘制

Player Control Thread
  命令、状态机、open/close/seek 协调

Demux Thread
  av_read_frame()，分发音视频 Packet

Audio Decode Thread
  解码、重采样、输出 PCM

Video Decode Thread
  解码、格式整理、提交 VideoFrame

SDL Audio Callback Thread
  从 PCM RingBuffer 取数据，更新音频时钟

第一阶段先保证职责和退出路径清晰，不必急于减少线程数量。

5. FFmpeg 后端边界

对 FFmpeg 对象进行 RAII 封装，避免其生命周期泄漏到 Core 的其他部分。

class FFmpegDemuxer {
public:
    OpenResult open(const MediaSource& source);
    ReadResult read(PacketRef& packet);
    SeekResult seek(std::chrono::milliseconds position);
    void flush();
    void close();
};

class FFmpegDecoder {
public:
    DecodeResult send(const PacketRef& packet);
    DecodeResult receive(FrameRef& frame);
    void flush();
};

跨模块传递自己的 VideoFrame、AudioFrame 和 PacketRef 类型。第一版内部可以引用计数持有 AVFrame，但 UI 和渲染接口不要看到裸 AVFrame*。

6. 队列设计

至少准备 Audio/Video/Subtitle PacketQueue 和 FrameQueue。队列不要只按包数量限制，还应支持字节数和媒体时长限制。

struct QueueLimits {
    size_t maxItems;
    size_t maxBytes;
    std::chrono::milliseconds maxDuration;
};
  • flush()：丢弃旧数据
  • abort()：立即唤醒阻塞线程并退出
  • close()：停止接收新数据，但可消费剩余数据
  • reset()：为下一阶段恢复队列

使用条件变量和取消令牌做背压，不要通过循环 sleep(5ms) 忙等。

7. SDL2 只负责音频输出

class IAudioSink {
public:
    virtual ~IAudioSink() = default;
    virtual AudioFormat open(const AudioFormat& preferred) = 0;
    virtual void start() = 0;
    virtual void pause() = 0;
    virtual void flush() = 0;
    virtual void close() = 0;
    virtual AudioClockSnapshot clock() const = 0;
};
AudioDecoder → AudioRingBuffer → SDL audio callback → Sound device

推荐 SDL callback + PCM RingBuffer，以便计算已播放样本数、设备延迟、欠载和精确音频时钟。第一版也可使用 SDL_QueueAudio()，但必须封装在 SDL2AudioSink 内。

8. 视频输出边界

class IVideoSink {
public:
    virtual ~IVideoSink() = default;
    virtual void submit(VideoFrame frame) = 0;
    virtual void flush() = 0;
    virtual void setFormat(const VideoFormat& format) = 0;
};

实现 QtVideoFrameBridge 作为 Core 与 Qt 渲染层之间的桥梁。推荐使用 latest-frame mailbox，而不是让渲染层消费无限增长的帧队列。

Video scheduler → Latest-frame mailbox → QQuickFramebufferObject Renderer

9. QQuickFramebufferObject 设计

拆成三个对象：

  • VideoOutputItem：QML 属性和 update 触发，位于 GUI 线程
  • VideoOutputRenderer：OpenGL 资源和绘制，位于 Qt 渲染线程
  • QtVideoFrameBridge：播放器内核与渲染层之间的帧邮箱

synchronize() 中仅做轻量状态和帧引用转移，不要在这里进行解码、sws_scale()、大块像素拷贝、Shader 编译或长时间锁等待。

void VideoOutputRenderer::synchronize(
    QQuickFramebufferObject* object)
{
    auto* item = static_cast<VideoOutputItem*>(object);
    bridge_ = item->frameBridge();
    fillMode_ = item->fillMode();
    if (bridge_) {
        pendingFrame_ = bridge_->acquireLatestFrame();
    }
}
注意：QQuickFramebufferObject 只适用于 Qt Quick 使用 OpenGL 渲染后端的场景。若未来要求 Vulkan、Metal 或 Qt RHI，应另做视频渲染适配器。

10. 视频像素格式策略

第一版先规范化为 YUV420P：

Decoder output
  ├─ YUV420P → 原样提交
  └─ 其他格式 → sws_scale → YUV420P

Y/U/V plane → GL_R8 textures → Fragment Shader → RGB

接口层预留 YUV420P、NV12、RGBA、HardwareSurface，并在 VideoFrame 中携带色彩空间、范围、原色、传递函数、SAR 和旋转信息。

11. 音视频同步

建立独立 MediaClock，视频解码器不直接操作 SDL，也不通过长时间 sleep 自行同步。

  • 存在音频时：AudioClock 作为主时钟
  • 无音频时：Monotonic/System Clock 作为主时钟
  • 外部同步时：External Clock 作为主时钟
delta = videoPts - masterClock.now()

视频明显超前 → 可中断等待
接近目标时间 → 提交 VideoSink
视频明显落后 → 按策略丢帧

12. Seek 流程

  1. 状态切换为 Seeking
  2. 暂停向输出提交新数据
  3. 唤醒所有阻塞队列
  4. 清空 PacketQueue 和 FrameQueue
  5. Flush 音频和视频输出
  6. 调用 avcodec_flush_buffers()
  7. 调用 avformat_seek_file()
  8. 重置主时钟
  9. 恢复队列并从新位置解码
  10. 回到 Playing 或 Paused

为 Seek 命令、Packet 和 Frame 增加 generation。旧 generation 的异步帧到达时直接丢弃，避免旧数据污染新时间点。

13. Session 生命周期

Player
  └─ PlaybackSession #42
      ├─ Demuxer
      ├─ Decoders
      ├─ Queues
      ├─ Clock
      └─ CancellationSource

每次 open 创建独立 Session。切换媒体时先取消旧 Session、等待线程退出、释放资源，再创建新 Session。所有异步事件携带 sessionId，Qt 层忽略旧 Session 的迟到事件。

15. 可测试性设计

提供 FakeAudioSink、FakeVideoSink、FakeClock、FakeDemuxer 和 FakeDecoder，让核心逻辑不依赖真实窗口和声卡即可测试。

  • 打开失败是否回到稳定状态
  • Stop 是否唤醒所有阻塞线程
  • 连续 Seek 是否只保留最终结果
  • 纯音频、纯视频是否可正常处理
  • EOF 后是否正确 Drain 解码器
  • 切换文件后是否屏蔽旧 Session 事件
  • Renderer 销毁后是否仍提交帧

16. 推荐实现顺序

第一阶段：建立边界

IPlayer、PlayerEvent、PlaybackSession、FFmpegDemuxer、FFmpegDecoder、SDL2AudioSink、QtVideoFrameBridge 和 QQuickFramebufferObject Renderer。

第二阶段：正确性

Session/generation、错误恢复、Drain/EOF、队列背压、可中断等待、连续 Seek、资源释放和单元测试。

第三阶段：扩展能力

字幕、多轨切换、倍速、截图、网络缓冲、断线重连、硬件解码、多像素格式以及录像或转码 Tap。

17. 关键避坑点

  1. 不要通过 Qt 信号裸传 AVFrame*，必须明确所有权和释放时机。
  2. 不要让 PlayerController 直接创建并调度全部 Worker。
  3. 不要让解码线程直接调用 QML 对象。
  4. 不要让渲染线程访问解码器的可变状态。
  5. 不要用固定延时等待模块初始化完成，应使用 Ready 事件。
  6. 不要用不可中断 sleep 做同步。
  7. SDL 只负责音频，视频统一交给 Qt Quick 渲染链。
  8. 为未来非 OpenGL 后端预留新的渲染适配器。

最终目标：形成的不是一个与 Qt 页面紧耦合的播放器，而是一个可被不同 UI、不同音频后端、不同解码后端和不同视频渲染器复用的播放器内核。
